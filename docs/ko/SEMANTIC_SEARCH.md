# CPU 의미 검색 실험

이 경로는 공개판의 실험적 적응 프로필입니다. 개발 원본의 PostgreSQL·OpenSearch 및 기존 청크 색인을 복원하지 않으며, 검색 품질 동등성은 검증되지 않았습니다. LLM과 OCR은 이 기능에 연결되지 않습니다.

1. 기본 설치 후 `scripts/install-ai.ps1`로 별도 AI 의존성을 설치합니다. `requirements-windows-ai.lock`의 Windows Python 3.12 패키지 버전을 사용합니다. Python 패키지 다운로드와 추가 디스크 공간이 필요하며 패키지 파일 자체의 해시 고정은 아직 제공하지 않습니다.
2. [모델 아티팩트 안내](MODEL_ARTIFACTS.md)를 읽고 사용자가 동의한 경우 임베딩 모델을 별도의 폴더에 받습니다. 모델 파일은 Git에 포함되지 않습니다.
3. 사용 권한이 있는 텍스트 PDF를 `문헌 관리`에서 등록합니다.
4. `문헌 검색` → `실험: CPU 의미 검색`에서 모델 폴더를 지정하고 `모델 파일 확인 및 로드`를 누릅니다. 파일 크기와 해시를 검사하고, CPU에 로컬 파일만 로드합니다. 시간이 걸릴 수 있습니다.
5. `의미 색인 생성 또는 갱신`을 누른 다음 의미 검색어를 입력하고 검색합니다. 결과에는 추출 텍스트의 페이지와 글자 범위, 해당 원문이 표시됩니다. PDF의 시각적 위치와 정확한 글자 범위가 일치한다는 뜻은 아닙니다.
6. 선택적으로 리랭커 모델을 같은 폴더에 설치하고 `리랭커 파일 확인 및 로드`, `검색 결과 리랭킹 사용`을 선택한 뒤 검색합니다. 의미 검색 상위 10개 구간만 리랭킹합니다. 표시된 리랭커 점수는 확률이 아닌 모델의 원시 점수입니다. 두 모델이 동시에 CPU 메모리를 사용합니다.

색인은 최대 2,000개 텍스트 구간을 지원하고 페이지당 1,000자 창을 200자 겹쳐 생성합니다. 색인 중 오류가 나면 기존 색인을 유지합니다. 문헌이나 페이지 텍스트가 변경되면 이전 색인을 사용하지 않으며 다시 만들어야 합니다. 데이터베이스를 백업할 때 사용자 문헌과 함께 벡터 색인도 포함됩니다.

검색 점수는 근거의 정확성, 주장 지지 여부 또는 표절을 확정하지 않습니다. 현재는 CPU만 사용하며 GPU·대규모 코퍼스·다른 하드웨어의 성능은 미검증입니다. 추출이 안 된 스캔 PDF는 OCR이 없어 색인되지 않습니다. 색인과 모델 설정을 변경하면 결과가 달라질 수 있습니다.

2026-10-28 Windows에서 독립 가상환경과 개발 모델의 임시 복사본으로 합성 PDF 두 페이지의 실제 임베딩 검색과 리랭킹을 CPU에서 시험하고 각 페이지 출처를 확인했습니다. 이는 모델 파일을 공식 서버에서 처음부터 다운로드한 설치 시험이나 검색 품질 평가가 아닙니다. 모의 모델 시험은 출처 범위, 문헌 변경 시 이전 색인 사용 차단, 색인 손상 감지 및 실패 시 기존 색인 보존을 확인합니다.
