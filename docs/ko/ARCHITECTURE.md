# 배포 설계와 기능 상태

## 사용자 경험

Windows 사용자는 저장소를 내려받고 Python 3.12를 설치한 뒤 설치 스크립트를 실행합니다. 앱은 `127.0.0.1`의 브라우저에서 열리고 처음에는 문헌이 0건입니다. 사용 권한이 있는 PDF를 등록하면 이 PC의 SQLite DB에 PDF와 페이지별 추출 텍스트가 저장됩니다. 텍스트 검색과 문자 일치 검사는 이 데이터를 사용합니다.

선택적으로 사용자가 모델 라이선스·용량을 확인하고 임베딩 및 리랭커 파일을 공식 배포처에서 별도로 받을 수 있습니다. 모델과 Python AI 의존성을 준비한 뒤 실험 CPU 검색에서 색인을 만듭니다. Git 저장소에는 모델 가중치, 개발자 문헌과 색인이 들어가지 않습니다. 사용자가 등록한 문헌은 개발자의 220개 문헌을 복원하는 것이 아니며 문헌과 설정에 따라 결과가 달라집니다.

## 현재 구현과 목표

| 항목 | 현재 후보 | 목표 대비 |
|---|---|---|
| 문헌 | PDF 개별 등록, 중복 확인, 제목 변경, 삭제, 페이지 텍스트 추출 | 일괄 등록·OCR·중단 복구 미구현 |
| 검색 | 문자 일치; 선택적 CPU 임베딩 및 상위 10개 리랭킹 | 원본 PostgreSQL/OpenSearch·Hybrid 및 품질 동등성 미검증 |
| 원고·보고 | 정확한 문장 일치와 로컬 Markdown 보고서 | 원본 문자·어절 검사 및 선행연구 비교와 동등하지 않음 |
| 개념 | 사용자 작성 개념과 문헌 연결, 이력, 초기 스키마 | 원본 분류 체계 이식, 동의어·병합·관계 승인 미구현 |
| 모델 설치 | 모델 파일 revision·해시 명세, 사용자 동의 후 별도 다운로드 | 전체 신규 다운로드 및 GPT-OSS 추론 경로 미검증 |
| 하드웨어 | Windows 읽기 전용 진단, CPU 실험 | GPU VRAM 측정과 자동 적응 미구현 |

현재 구조는 **적응 프로필**이며 원본과 동일한 reference 프로필이 아닙니다. 기존 제품의 인용 검증, 청크·검색 품질, 모델 출력과 동일하다고 주장하지 않습니다. 구간에 표시된 추출 텍스트와 PDF 페이지를 사람이 확인해야 합니다.

## 데이터 흐름

`PDF → SHA-256·페이지 텍스트 → SQLite → 문자 검색 또는 선택적 벡터 색인 → 페이지·문자 범위 결과`

색인은 로컬 DB에 저장되며 문헌 텍스트가 바뀌면 재생성이 필요합니다. 사용자 승인 없이 PDF나 검색어를 모델 제공자에게 전송하는 기능은 구현하지 않았습니다. 패키지·모델 설치 시에는 해당 배포처에 접속합니다. 앱은 로컬 사용을 전제로 하며 별도 사용자 인증이 없으므로 공유 PC와 다른 로컬 프로세스의 접근을 고려하세요.

## 공개와 권리

개발 원본과 독립 Git 이력을 사용합니다. [파일 허용목록](../../PUBLIC_FILES.txt)과 간단한 이력 검사는 유출 가능성을 줄이는 기술 수단이며 저작권·기관 승인이나 완전한 보안 감사가 아닙니다. 저장소 코드는 [Apache-2.0](../../LICENSE)으로 제공하며, 다운로드하는 의존성·모델 및 사용자가 등록하는 문헌은 각자의 라이선스와 권리가 적용됩니다. 이 후보는 전체 설치 검증이나 원본 제품 동등성 승인을 받은 완성 릴리스가 아닙니다.
